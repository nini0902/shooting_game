# Feature Specification: 初學者俯視射擊遊戲

**Feature Branch**: `001-beginner-topdown-shooter`  
**Created**: 2026-03-19  
**Status**: Draft  
**Input**: User description: "Create a beginner-friendly top-down shooter game"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 玩家可操作角色並進行射擊 (Priority: P1)

作為第一次接觸此遊戲的玩家，我可以移動角色並發射子彈，立即感受到可操作且有回饋的遊戲體驗。

**Why this priority**: 角色移動與射擊是核心可玩性，若缺少此能力，遊戲無法成立。

**Independent Test**: 啟動遊戲後僅驗證角色移動與射擊，不依賴敵人系統，也可確認輸入與視覺回饋是否正常。

**Acceptance Scenarios**:

1. **Given** 遊戲在進行中，**When** 玩家按下 W、A、S、D，**Then** 角色朝對應方向移動，且不會停止更新畫面。
2. **Given** 遊戲在進行中，**When** 玩家觸發射擊輸入，**Then** 畫面出現子彈並沿固定方向前進。

---

### User Story 2 - 玩家可透過戰鬥獲得分數並承受傷害 (Priority: P2)

作為玩家，我希望敵人持續出現並追擊我，當子彈命中敵人會消滅敵人並累計分數，同時角色受攻擊會扣血。

**Why this priority**: 追擊、命中與受傷形成基本挑戰循環，是遊戲目標與風險來源。

**Independent Test**: 在可移動與可射擊前提下，驗證敵人生成、追擊、碰撞後消失、分數增加與生命扣減。

**Acceptance Scenarios**:

1. **Given** 遊戲在進行中，**When** 到達敵人生成條件，**Then** 新敵人出現在場景並朝玩家位置移動。
2. **Given** 子彈與敵人發生碰撞，**When** 碰撞被偵測，**Then** 該敵人被移除且分數增加。
3. **Given** 敵人與玩家發生碰撞，**When** 碰撞被偵測，**Then** 玩家生命值下降並在畫面更新後可見。

---

### User Story 3 - 玩家可讀取狀態並在失敗後重開 (Priority: P3)

作為玩家，我可以隨時看到目前分數與生命，當生命歸零時看到明確結束訊息，並可用單鍵重新開始。

**Why this priority**: 狀態可見性與重開機制可提升可理解性與重玩意願，特別適合初學者。

**Independent Test**: 強制將生命降至 0，驗證 Game Over 顯示與 R 鍵重開流程，確認狀態重置正確。

**Acceptance Scenarios**:

1. **Given** 遊戲在進行中，**When** 畫面刷新，**Then** 分數與生命值皆持續顯示在可辨識位置。
2. **Given** 玩家生命值為 0，**When** 進入結束狀態，**Then** 畫面顯示 Game Over 且停止一般戰鬥更新。
3. **Given** 遊戲處於結束狀態，**When** 玩家按下 R，**Then** 遊戲重置為新局（生命、分數、敵人、子彈狀態重設）。

### Edge Cases

- 玩家同時按下多個移動鍵時，系統需維持可預期的移動結果，不可造成程式錯誤或停滯。
- 單一畫面更新內若發生多組碰撞，需正確處理所有有效碰撞，不可遺漏或重複計分。
- 玩家生命在同一更新步驟內降到 0 或以下時，遊戲需立即進入結束狀態且不再繼續一般戰鬥判定。
- 在 Game Over 後按非 R 鍵不應重開；按 R 應可在一次輸入內成功重啟。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 提供單一可執行程式檔作為完整遊戲入口，使用者不需啟動多個程式。
- **FR-002**: 系統 MUST 允許玩家使用 W、A、S、D 控制角色於遊戲區域內移動。
- **FR-003**: 系統 MUST 允許玩家在遊戲進行中發射子彈，且每次射擊都能產生可見的子彈物件。
- **FR-004**: 系統 MUST 週期性生成敵人，並使敵人持續朝玩家當前位置移動。
- **FR-005**: 系統 MUST 在子彈與敵人碰撞時移除敵人，並對玩家分數增加固定增量。
- **FR-006**: 系統 MUST 維護玩家生命值，並在敵人命中玩家時降低生命值。
- **FR-007**: 系統 MUST 在遊戲進行中持續顯示目前分數與生命值。
- **FR-008**: 系統 MUST 在生命值降至 0 時顯示 Game Over，並切換為不可繼續戰鬥的結束狀態。
- **FR-009**: 系統 MUST 在結束狀態下允許玩家按 R 重新開始，且重置本局所有遊戲狀態。
- **FR-010**: 系統 MUST 僅使用基礎幾何圖形呈現玩家、敵人與子彈，不依賴外部圖片素材。
- **FR-011**: 系統 MUST 在關鍵遊戲邏輯處提供清楚註解，讓初學者可理解主要流程與規則。
- **FR-012**: 系統 MUST 以初學者可讀性為優先，保持一致命名與簡潔流程，避免不必要複雜機制。

### Constitutional Requirements *(mandatory)*

- **CR-001**: 每個階段開始與結束都 MUST 執行 `git status` 並確認狀態正常。
- **CR-002**: 實作策略 MUST 採 TDD（先測試、紅燈、實作、綠燈、重構）。
- **CR-003**: `implement` 階段 MUST 維護 `tasks.md` 勾選狀態與實際進度一致。
- **CR-004**: 實作流程 MUST 保護規格文件，不得刪除或覆蓋 `spec.md`、`plan.md`、`tasks.md`、`constitution.md`。
- **CR-005**: 若為網站專案，解決方案 MUST 以前端靜態網站為預設且可部署於 GitHub Pages；本功能為非網站專案，此條僅記錄為不適用之治理約束。

### Key Entities *(include if feature involves data)*

- **Player**: 玩家角色狀態，包含位置、移動方向、生命值與是否存活。
- **Bullet**: 玩家發射的投射物，包含位置、移動方向、速度與有效狀態。
- **Enemy**: 追擊玩家的敵方單位，包含位置、移動速度與有效狀態。
- **Game Session State**: 單局遊戲狀態，包含當前分數、是否 Game Over、可否重開。

## Assumptions

- 預設以單人本機遊玩為範圍，不含多人連線與帳號系統。
- 預設採固定大小遊戲視窗與單一遊玩場景，不包含關卡切換。
- 預設分數計算採單一規則（每消滅一名敵人增加固定分數）。
- 預設生命值下限為 0，顯示與判定以整數值處理。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 90% 以上首次遊玩者可在 1 分鐘內完成「移動、射擊、命中敵人一次」的核心操作。
- **SC-002**: 在 10 分鐘連續遊玩中，分數與生命值顯示正確率達 100%（不出現漏更新或錯誤值）。
- **SC-003**: 當生命歸零時，Game Over 訊息於 1 秒內可見，且玩家可於 5 秒內成功以 R 開啟新局。
- **SC-004**: 由初學者進行可讀性檢查時，至少 80% 關鍵邏輯區塊可在不額外說明下描述其用途。
